## 核心概念

### 图像是离散的采样

计算机图形学的输出往往是一幅**光栅图像**：二维网格上的每个格子（**像素**）存颜色（以及可选的深度、模板等）。FoCG 强调：连续的光场/几何被**采样与量化**后才进入显示设备；走样（aliasing）、过滤、gamma 等问题都源于「连续 → 离散」这一步。

实时渲染里，这份可展示的颜色阵列通常称为**颜色缓冲（color buffer）**；与之配套的还有**深度缓冲（depth / Z-buffer）**、**模板缓冲（stencil）** 等。一组相关缓冲常合称**帧缓冲（framebuffer）**。双缓冲（front / back）用来避免撕裂：在后缓冲画完再交换到前台。

### 「管线」是什么意思

**图形管线（graphics pipeline）**把「描述场景」变成「填充帧缓冲」拆成一串阶段。好处：

1. **阶段语义清晰**：顶点变形、裁剪、光栅化、片元着色各司其职。
2. **硬件可流水线化**：前一批三角形还在光栅时，下一批顶点已在变换。
3. **可编程插入点固定**：现代 API 不允许你随意改所有阶段，但开放了着色器等关键插槽。

LearnOpenGL 把现代 OpenGL 描述为**可编程管线**：你必须提供至少顶点着色器与片元着色器；许多旧版固定功能（如固定功能变换矩阵栈）已从 core profile 移除。

### 从应用到达 GPU

CPU 侧（应用）典型职责：

1. 准备**顶点数据**（位置、法线、UV、颜色……）与可选**索引**。
2. 上传到 GPU 缓冲对象（OpenGL：VBO / EBO 等）。
3. 配置**顶点属性布局**（哪个属性对应缓冲里哪一段）。
4. 绑定着色器程序、纹理、Uniform 状态。
5. 发出 **Draw Call**（`glDrawArrays` / `glDrawElements` 等）。

之后控制权主要在 GPU：顶点着色器逐顶点执行 → 图元装配 →（可选曲面细分/几何着色器）→ 裁剪 → 光栅化 → 片元着色器 → 逐片元测试与混合 → 写入帧缓冲。

### 阶段鸟瞰（概念顺序）

下面按**教学用逻辑顺序**列出，具体 API/硬件可能合并或重排部分步骤：

| 阶段 | 输入 → 输出（直觉） | 可编程？ |
|------|---------------------|----------|
| 顶点着色（Vertex Shader） | 每顶点属性 → 裁剪空间位置 + 传给后续的 varyings | 是（必写） |
| 图元装配 | 顶点流 → 点/线/三角形 | 固定 |
| 曲面细分 / 几何着色器 | 可选：放大或改写图元 | 可选可编程 |
| 裁剪 | 落在视锥/裁剪体外的部分被切掉 | 固定 |
| 透视除法与视口变换 | 裁剪坐标 → NDC → 窗口坐标 | 固定（参数可配） |
| 光栅化 | 图元 → 片元（候选像素 + 插值属性） | 固定 |
| 片元着色（Fragment Shader） | 每片元 → 颜色（及可选深度） | 是（必写） |
| 逐片元测试与混合 | 深度/模板/alpha 等 → 是否写入及如何与原色混合 | 多为固定功能 + 状态机 |

**片元（fragment）**≠ 最终像素：同一像素可能对应多个片元候选（多重采样、半透明叠加、被深度测试杀掉的片元等）。片元是「着色器算出来的一次候选写回」。

### 光栅化：覆盖与插值

对三角形，光栅化要回答两件事：

1. **覆盖（coverage）**：哪些像素中心（或采样点）落在三角形内？
2. **属性插值**：顶点上的颜色、UV、法线等，如何赋给内部片元？

重心坐标（barycentric coordinates）\(\alpha, \beta, \gamma\)（\(\alpha+\beta+\gamma=1\)）是标准工具：片元属性 \(\phi = \alpha\phi_0 + \beta\phi_1 + \gamma\phi_2\)。透视投影下，**屏幕空间线性插值**对某些属性不正确，需要**透视校正插值**（对 \(1/w\) 等做处理）——这是 FoCG 光栅化章节与实践中「纹理在大透视三角形上发糊/扭曲」类问题的根。

### 遮挡：Z-buffer 思想

画家算法从远到近画，半透明友好但排序昂贵且难处理相交。实时图形主流是 **Z-buffer**：

- 每个像素另存当前最近深度。
- 新片元若比已有深度更近（通过深度测试），则更新颜色与深度；否则丢弃。

深度值通常来自顶点变换后的 \(z\)（经透视与视口映射）。非线性的 NDC 深度分布会导致远处精度变差——这是阴影痤疮、远平面过远时闪烁等问题的常见背景。

### 与光线追踪的对比（定位用）

FoCG 同时讲授光线追踪与光栅化。本章管线指**光栅化实时路径**：以图元为中心，推到像素。光线追踪以光线为中心，问「这像素看见了什么」。二者可混合（混合渲染），但入门时先把光栅管线走通，避免概念搅在一起。

## 实践对照：一次「Hello Triangle」在管线里的位置

LearnOpenGL 的第一三角形，本质上是：

1. CPU 准备三个顶点的位置（往往已在 NDC 或经 VS 输出到裁剪空间）。
2. VS 几乎原样写出 `gl_Position`。
3. 光栅化生成覆盖片元。
4. FS 输出常数颜色或简单 varying 颜色。
5. 颜色写入默认帧缓冲，交换到窗口。

它刻意省略了模型矩阵、相机、纹理——但**阶段骨架已经齐全**。后续章节只是在 VS/FS 与 CPU 状态里填入更丰富的数据。

```cpp
// 概念示意：一次索引绘制（省略错误检查与窗口代码）
glUseProgram(program);
glBindVertexArray(vao);
glDrawElements(GL_TRIANGLES, indexCount, GL_UNSIGNED_INT, 0);
```

```glsl
// 最小顶点着色器（NDC 三角形）
#version 330 core
layout (location = 0) in vec3 aPos;
void main() {
    gl_Position = vec4(aPos, 1.0);
}
```

```glsl
// 最小片元着色器
#version 330 core
out vec4 FragColor;
void main() {
    FragColor = vec4(0.2, 0.7, 0.9, 1.0);
}
```

## 坐标系预告（下章展开）

即使本章不深挖矩阵，也需要先记住名字，避免后面迷路：

| 空间 | 含义（直觉） |
|------|----------------|
| 局部 / 模型 | 网格自身坐标 |
| 世界 | 场景共用坐标 |
| 观察 / 视图 / 相机 | 以相机为原点的坐标 |
| 裁剪 | VS 输出的齐次坐标；供裁剪与透视除法 |
| NDC | 透视除法后通常约在 \([-1,1]^3\)（API 相关） |
| 屏幕 / 窗口 | 像素坐标 |

LearnOpenGL「Coordinate Systems」一节与 FoCG 的 viewing / projection 章节描述的是同一条链；差别主要在记号与 API 绑定方式。

## 易错点

- **把「片元着色器」当成「只跑一次的像素着色」**：它按片元（采样）执行，同一像素可能多次；也受早期深度测试等优化影响。
- **以为 VS 输出的就是像素坐标**：`gl_Position` 是**裁剪空间齐次坐标**；透视除法与视口变换在固定阶段完成。
- **忽略索引绕序 / 正面判定**：默认（可配置）以绕序区分正反面；背面剔除打开时三角形「消失」常常是绕序或相机方向反了。
- **CPU 改了缓冲却忘了绑定正确的 VAO/VBO**：状态机 API 下「绑错对象」是静默黑屏的高频原因。
- **深度测试未开或清屏未清深度**：近的物体被远的挡住，或残留上一帧深度。

## 练习指引

- 对照 LearnOpenGL Hello Triangle，在纸上画出：VBO 里的字节 → 属性指针 → VS → 光栅 → FS → 颜色缓冲。标出哪一步是可编程的。
- 故意把三角形三个顶点的绕序反转，打开 `glEnable(GL_CULL_FACE)`，观察是否被剔除；再关掉剔除对比。
- 将 FS 改为使用 `gl_FragCoord.xy` 生成简单渐变，理解片元着色器拿到的是窗口相关坐标。
- 阅读 FoCG 中光栅化 / 深度缓冲相关段落，用自己的话写五句：覆盖测试、重心插值、透视校正、Z-buffer、与光线追踪的分工。
- 预习：单位向量、点积、矩阵乘法——没有它们就无法严肃讨论相机与模型变换（[第 2 章](./ch02-vectors-transforms.md)）。

## 小结

- 实时 3D 的主路径是**光栅化管线**：顶点处理 → 图元 → 光栅 → 片元处理 → 帧缓冲。
- **帧缓冲**是离散图像 + 辅助缓冲；显示通常经双缓冲交换。
- **顶点/片元着色器**是现代管线必须填充的可编程核心；裁剪、光栅、深度测试等多为固定功能。
- 光栅化解决**覆盖**与**属性插值**；Z-buffer 解决多数不透明遮挡。
- Hello Triangle 已是完整闭环；后续只是在同一骨架上增加变换、纹理与光照。
